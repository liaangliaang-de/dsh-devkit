# 0.2.7 准入修复

报告中的错误 `DEVKIT: no managed direct-user coding task` 来自正常准入检查，被错误用于纯状态和材料查询，导致用户了解插件时工具就报错。自然语言识别同时漏掉了常见新增功能请求。

修复分开两种行为：未接管时允许直接根会话读取status、query和checkpoint；查询只生成材料缓存，不创建编码契约。创建、修改、执行、浏览器和执行产物工具仍需要真实用户编码请求，未接管时返回结构化说明。模型自行plan不会激活任务。

| 表达 | 修复后的判定 |
|---|---|
| dsh-devkit装了个新插件你看看有什么用 | discussion，只读 |
| 他报错了吗 | discussion，只读 |
| 帮我看看这个插件有什么用 / 这个插件怎么用 | discussion，只读 |
| 能不能加个导出功能 / 我想做一个待办清单 | work |
| 这个功能有点问题 / 页面打不开 | work（具体对象故障） |
| 太慢了 | 有本会话编码上下文才作为修订，首次无对象不自动接管 |

不能把“看”“怎么用”简单加入写入准入正则；询问不等于授权修改。口语识别仍为启发式，这个补丁不承诺理解所有表达。

另修复两个状态问题：agent创建时只有本会话历史work才恢复受管身份，旧unknown消息不自动重分类；模糊反馈只参考本会话的work上下文，不借用其他会话。旧任务数据、版本与回执保留。

# DSH DevKit

面向「许愿式编程」的 DeepSeek Harness 单包增强实验。

**一个安装包，一个插件入口，直接用自然语言描述需求。** 提供仓库材料、片段编辑、本地应用生成、真实验收和长任务状态约束。用户不需要选择一长串 skill。

> **当前状态：0.2.7 实验版。** 修复未接管任务时状态/查询工具报错、常见新增功能请求漏判，以及旧unknown会话恢复时错误接管的问题。已有实际执行代码和原生集成测试，但真实模型仍会绕圈、过度读取或未完成自主交付。尚不能证明整体质量、token 或费用大幅改善。请先阅读[本次回归](docs/admission-fix.md)、[历史验收结果](docs/validation.md)和[兼容矩阵](docs/compatibility.md)。

## 能做什么

| 能力 | 实现 |
|---|---|
| 许愿与口语反馈 | 将原话、默认假设和需求版本分开；已有项目的“没反应”“太乱”等可进入修订 |
| 仓库材料 | 解析 JS/TS/JSX/TSX 符号和导入，选取有界片段；按文件内容和解析器版本缓存 |
| 精准修改 | 用绑定工作区、需求版本、文件哈希的片段引用交给原生 read/edit；旧引用拒绝 |
| 本地应用生成 | 用业务字段与统计配置生成表单、列表、统计、localStorage 和 CSV；拒绝覆盖已有应用 |
| 真实验收 | 命令及浏览器操作留下执行回执，检查增删记录、刷新保留、下载内容；新建应用自动冒烟 |
| 长任务接续 | 有依赖的里程碑、证据失效、checkpoint、取消、重复结果去重、中断恢复；未知副作用不自动重放 |
| 上下文与预算 | 单状态源、单系统策略段、单动态上下文；累计请求与可选提供商 usage 阈值 |

内部工具包括 `devkit_project`、`devkit_context`、`devkit_patch`、`devkit_create`、`devkit_verify`、`devkit_artifact`、`devkit_browser`，由主模型使用，不另外启动监督模型或压缩循环。

## 安装

1. 从 [Releases](https://github.com/liaangliaang-de/dsh-devkit/releases) 下载实验版安装包。
2. 在 DSH 的添加插件入口选择其中的 `dsh-devkit-0.2.7.tgz`，启用 `dsh-devkit`。也可退出 DSH 后运行安装包中的 `Install.cmd`。
3. 打开独立项目目录，直接说你的需求。

例如：“做个自己用的记账小网页，能记录收支、看余额、导出 CSV，不要登录。”“这个导出点了没反应，修好就行。”“标题改成我的小账本，保留我新增的备注文件。”

“看看这个插件有什么用”“他报错了吗”保持只读，未接管时也可查询状态和仓库材料。“能不能加个导出功能”“页面打不开”等可进入编码任务；模型调用工具本身不会代替用户授权，不能靠自行调用 `plan` 激活任务。

已验证 Windows DSH **0.2.1-rc.1**。浏览器复用本机 Chrome/Edge，不下载浏览器、不自动提高权限。受测机器在 `workspace-write` 下有 Chrome crashpad 启动失败；完整权限只在隔离试验中验证，不代表建议对所有项目开放权限。安装、数据位置、旧依赖解析失败及卸载说明见[安装文档](docs/installation.md)。

## 开发

需要 Node.js 22.19+（CI 使用 Node.js 24）：

```sh
npm ci --ignore-scripts
npm run build
npm test
npm pack
```

CI 只做构建、单元测试、包检查，不使用 DSH 账号或模型额度。可选的真实原生入口测试使用隔离 profile，并通过代码拒绝模型推理，见[测试说明](docs/testing.md)。

代码布局、状态边界见[架构说明](docs/architecture.md)。欢迎用最小复现反馈问题；请区分单元、原生工具和真实模型层的结果。

## 限制与许可

不是完整 LSP、跨语言语义分析或自主项目经理；口语识别为启发式。文件预检不能消除运行中 shell 与外部编辑的竞态，测试覆盖充分性不能由 criterion 编号自动证明。已报告 token 阈值只阻止后续请求，不是进行中请求的绝对硬上限。
